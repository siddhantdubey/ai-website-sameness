01 — How a week runs

A Monday with Docket

No grooming session, no hour-long standup. Most teams spend about fifteen minutes on Docket a week, and nearly all of it is on Monday.

8:00

The draft writes itself

Anything unfinished from last week carries over and gets marked. Items from linked GitHub issues and Linear imports drop in underneath.

9:15

A lead trims it

Drag things into "Not this week." Assign owners. If a list is longer than one screen, Docket will politely ask whether you're sure.

9:40

It goes out

One message to Slack, Teams, or email. Plain text, readable on a phone, no login needed to see it.

Fri 4:00

It closes

Whatever's done gets archived into a running log you can search later. Whatever isn't, waits for Monday.

02 — What we didn't build

Left out on purpose

Every one of these has been requested, more than once. We said no because each one turns a list people read into a system people maintain.

Gantt chartsIf your week needs a dependency graph, the week is too big.
Story pointsAn item is either happening this week or it isn't.
Custom fieldsYou get a title, an owner, a link, and a note. That's been enough for six years.
Burndown chartsThe list is short enough to see whether you're on track.
Seven kinds of statusShipping, stuck, not this week. Done is a checkbox.
Notifications for everythingOne message on Monday. One on Friday if you want it. That's it.
